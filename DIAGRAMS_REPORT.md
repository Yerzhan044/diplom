## 📊 Содержание каждой диаграммы

### Диаграмма 1: Поток данных (Data Flow)

```
Входные данные
  ↓ Feature Engineering
  ↓ Supervised Ensemble
  ↓ Unsupervised Anomaly
  ↓ Rule Engine
  ↓ SHAP XAI
  ↓ Decision Aggregation
  ↓ [APPROVE / REVIEW / DECLINE]
  ↓ Security Logging
  ↓ JSONL файлы
```

**Используется в**: Глава 2.1 - Архитектура

### Диаграмма 2: Архитектура системы

```
API Layer (5 endpoints)
  ↓
Core Processing (Feature, ML, Rules, XAI)
  ↓
Models (4 ML модели)
  ↓
Storage (Logs, Artifacts)
  ↓
Frontend (Dashboard, CSV)
```

**Используется в**: Глава 2.1 - Архитектура

### Диаграмма 3: Ансамблевое голосование

```
Supervised: (3*RF + 3*ET + 2*GB) / 8
Anomaly: Isolation Forest
Rules: max(velocity, geo, behavioral)
  ↓
Final = 0.5*supervised + 0.2*anomaly + 0.3*rules
  ↓
[< 0.65: APPROVE | 0.65-0.85: REVIEW | ≥ 0.85: DECLINE]
```

**Используется в**: Глава 2.2 - ML подход, Глава 3 - Реализация

### Диаграмма 4: Компоненты системы

**Показывает**: Модули, их взаимосвязь, типы данных  
**Используется в**: Глава 2.1 - Архитектура

### Диаграмма 5: Дерево решений

**Показывает**: Полный процесс обработки одной транзакции  
**Используется в**: Глава 2.3 - Логика решений

### Диаграмма 6: Обучение моделей

**Показывает**: Train → Validation → Evaluation → Deployment → Production  
**Используется в**: Глава 3.2 - Обучение моделей

### Диаграмма 7: Логирование и аудит

**Показывает**: JSONL логирование, compliance, explainability  
**Используется в**: Глава 3.3 - Безопасность и аудит

## 🚀 Как использовать

### Вариант 1: Быстрый просмотр

```bash
# Откройте в браузере
open docs/diagrams_viewer.html
```

### Вариант 2: Редактирование

```

2. Скопируйте содержимое файла из docs/diagrams/
3. Редактируйте в интерактивном редакторе

```

